# 测量规则

这份规则约束本仓库里所有“A 比 B 快多少”的结论。目的只有一个：让差异来自代码，而不是来自环境。

测量机器是一台 RTX 3060 Laptop（6GB，WSL2，80 W 功耗墙）。它的时钟会随温度和功耗漂移，
之前的端到端对比就因为先后跑两组配置，混进了 1042–1207 MHz 对 1420 MHz 的时钟差异。

## 规则

1. **交替跑。** 要比较的配置按 `A B | B A | A B …` 的顺序轮流跑，每轮轮换起始位置。
   用 `experiments/compare.py`，不要手动先跑完一组再跑另一组。
2. **至少 5 轮。** 每个配置至少 5 次独立运行（每次是一个新进程）。报告均值和样本标准差。
3. **不挑结果。** 跑了几轮就汇总几轮。某一轮明显异常（比如后台程序抢占）可以整轮作废重跑，
   但要在结果里写明作废了哪一轮、原因是什么，并且同一轮里的所有配置一起作废。
4. **按轮配对算倍数。** 加速比用同一轮里两个配置的比值，再对各轮取均值和标准差。
   这样轮与轮之间的环境漂移会被抵消。
5. **记录环境。** 每条结果自带 commit、是否有未提交改动、PyTorch 和驱动版本，
   以及测量前后的 GPU 时钟、温度、功耗、占用（`cs336_basics/runinfo.py`）。
   测量前后时钟相差很大的运行要单独标出。
6. **预热不计时。** 前几步包含编译和 cuDNN/cuBLAS 的初始化，不计入测量（`--warmup-steps`）。
7. **设显存上限。** 一律带 `--memory-fraction 0.8`。WSL 下显存超限不会报 OOM，而是溢出到系统内存、
   慢 10–60 倍，带着这种运行算平均值没有意义。
8. **差异要大于噪声才算数。** 两个配置的差小于各自的标准差时，结论写“在当前噪声下看不出差异”。
9. **看长尾时加步数。** `step_ms_p99` 用最近秩法计算，测量步数少于 100 时它就是最大值。
   关心长尾（比如 GC 停顿）时把 `--measure-steps` 设到 200 以上。

## 测量前检查

- 接通电源，关闭微信、Steam、网易云等会占用 GPU 的程序；空载占用仍会有，随结果一起记录。
- 工作区没有未提交的改动（否则 `git_dirty` 为 true，结果对应不上任何一个 commit）。
